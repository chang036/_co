1EDA 是什麼：一句話與一個比喻

EDA（Electronic Design Automation，電子設計自動化）是用來設計、驗證、實現與分析晶片（及電路板）的一套軟體工具與方法學。對數位 IC 而言，它最重要的任務，是讓人類寫下的硬體描述（RTL），經過一連串自動化步驟，變成兩種最終產物之一：FPGA 的位元流（bitstream），或 ASIC 的 GDSII 版圖。

一句話定義

EDA 是硬體的編譯器、測試框架、排版軟體與量測儀器的總和：它把「我想要什麼功能」翻譯成「哪一顆閘放在哪裡、用哪一層金屬連起來」，並在做出來之前告訴你「這樣會不會太慢、太熱、太大、放不下」。

很多人第一次接觸 EDA，會以為它只是「畫電路圖的軟體」或「模擬器」。但真正商用 IC 設計的 EDA 是一條工具鏈，每一站都會改變設計的表示法（representation），也每一站都會加入新的物理限制：

軟體開發的類比IC / FPGA 的對應轉換了什麼
原始碼RTL（Veryl / Verilog / VHDL）人的意圖 → 可被工具解析的時序邏輯描述
編譯器邏輯合成（logic synthesis）RTL → 與製程無關的閘級網表（AND / OR / DFF…）
單元測試testbench、assertion、形式驗證用測試與數學證明檢查功能是否正確
連結器與最佳化技術映射（technology mapping）通用閘 → LUT4、標準元件、BRAM / SRAM
排版引擎佈局與繞線（placement & routing）邏輯連接 → 晶片上的實際座標與金屬線
效能分析器STA、功耗、IR drop、DRC / LVS「能不能跑」、「會不會燒」、「能不能做」
執行檔位元流 / GDSII可載入 FPGA，或可送進晶圓廠製造

這個比喻有一個關鍵差異：軟體編譯失敗可以重編，晶片做錯通常不能重來。 一組先進製程光罩動輒數百萬到數千萬美元，一次改版就是幾個月的時間。因此 EDA 不只是「讓設計變快」，更是「讓錯誤在便宜的時候就被抓到」。

2為什麼 IC 設計離不開 EDA

一顆現代處理器有數百億個電晶體，連線的數量與彼此的時序關係，早已超出人腦可以逐一手算的範圍。EDA 之所以不可取代，可以從四個壓力來看。

▦

規模：數量級問題

一個 256×8 的 FIFO，用通用閘描述就已是 8,660 個元件；一顆 RV32I 核心合成後是 9,151 個閘、5,337 個 LUT4、1,056 個 DFF。這種規模只能靠工具做階層展開、化簡與對應。

$

成本：錯誤很貴

FPGA 燒錯可以重燒；ASIC 光罩做錯，損失的是整套光罩與數個月產能。EDA 的驗證與簽核（signoff）流程，本質上是在把錯誤提前。

⚙

物理：互相拉扯的约束

速度、功耗、面積、良率不是獨立的。把元件排緊可以縮短線長，卻可能造成壅塞與 IR drop；提高時脈可以變快，卻可能讓功耗與時序餘裕惡化。

◈

設計空間：同一份 RTL，多種實現

同一份 FIFO 可以放進 FPGA（1 個 BRAM、60 個 LUT4），也可以做成 ASIC（166 個標準元件、1 個 SRAM）。哪個才對？要靠 EDA 把PPA（Performance / Power / Area）量出來再選。

PPA 是什麼

Performance（效能，常用 Fmax 或關鍵路徑延遲表示）、Power（功耗／每週期能量）、Area（面積）。這三個字幾乎是所有 IC 設計取捨的共同語言；EDA 的工作，就是讓這三個數字在每個階段都「看得見」。

還有一個常被忽略的作用：EDA 是團隊協作的共同語言。前端工程師交付 RTL 與 testbench，後端工程師交付佈局、時序與 DRC 報告，製程廠交付 PDK 與標準元件庫；大家靠同一套格式（Verilog、LEF/DEF、SDC、GDSII、SPEF…）溝通。沒有 EDA，這些角色無法交接。

驗證與分析貫穿全程：testbench · assertion · coverage · 形式等價 · 閘級模擬 · STA · 功耗 / IR drop · DRC / LVS。每一站都在回答同一件事：「這個設計真的能做出來，而且做出來會對嗎？」

3.1 前端與後端

前端關心「邏輯對不對」：RTL 撰寫、功能模擬、邏輯合成、形式驗證。輸出的是一份與製程無關（technology-independent）的閘級網表。後端關心「物理上做不做得到」：把閘對應到真正的標準元件或 FPGA 資源，安排位置、拉線、插入時脈樹，最後做時序、功耗、DRC / LVS 簽核。

兩者之間不是單向的。後端發現「這條路徑太慢」時，會回頭要求前端改微架構（多加一級 pipeline、拆開組合邏輯），或要求合成工具換一種映射策略。這種來回，就是 EDA 工具與設計者共同進行的設計空間探索。

本報告的 FIFO 正好把這個差異量化出來：同一個 RTL、同一組測試，FPGA 版本 Fmax 48.3 MHz、每週期 25.9 pJ；ASIC 版本 Fmax 493.9 MHz、每週期 0.70 pJ。但 ASIC 需要光罩與固定的標準元件庫，FPGA 則可以立刻重燒。這就是 EDA 幫人做的第一種取捨。

4.1 為什麼選這兩套，而不是直接開商用工具？

商用 ASIC EDA（Synopsys、Cadence、Siemens EDA）需要授權、PDK 與大量環境設定，通常只在學校或公司內部使用；它們的強項是「簽核級」的準確度與完整流程。相對地，veryl2chip 與 hack-computer 把整條流程攤開在瀏覽器裡，每個階段都能點進去看閘、LUT 真值表、標準元件、繞線與時序，非常適合理解「EDA 到底在做什麼」。兩者的定位不同：一個是產業的簽核工具，一個是透明可觀察的教學／研究工具。

Cornell ECE 5745 的課程講義則提供了另一個參照：它用 Synopsys / Cadence 教前端與後端，也講合成演算法（Topic 12）與實體設計演算法（Topic 13），並帶學生跑 OpenLANE 開源流程。這正好補上「商用工具怎麼用」與「工具背後演算法是什麼」兩塊。

5實作一：FIFO 256×8 的完整流程

第一個設計是 256×8 的同步 FIFO，資料在 i_pop 的下一拍出現，記憶體以同步讀取推斷成 block RAM。這個設計不大，卻包含了數位 IC 最典型的三件事：狀態（讀寫指標）、記憶體（RAM）、控制（full / empty），很適合走完整條流程。

5.1 設計與 testbench

FIFO 的核心邏輯如下（節錄自 veryl2chip 範例 fifo.veryl）：

module Fifo #(
    param ADDR_W: u32 = 8,
    param DATA_W: u32 = 8,
) (
    i_clk  : input  clock        ,
    i_rst  : input  reset        ,
    i_push : input  logic        ,
    i_data : input  logic<DATA_W>,
    i_pop  : input  logic        ,
    o_data : output logic<DATA_W>,
    o_empty: output logic        ,
    o_full : output logic        ,
    o_count: output logic<ADDR_W + 1>,
) {
    var mem  : logic<DATA_W> [1 << ADDR_W];
    var wp   : logic<ADDR_W>;
    var rp   : logic<ADDR_W>;
    var count: logic<ADDR_W + 1>;
    var rdata: logic<DATA_W>;

    let do_push: logic = i_push && (count != (1 << ADDR_W));
    let do_pop : logic = i_pop  && (count != 0);

    always_ff (i_clk) {
        if do_push { mem[wp] = i_data; }
        if do_pop  { rdata   = mem[rp]; }
    }

    always_ff {
        if_reset { wp = 0; rp = 0; count = 0; }
        else {
            if do_push { wp = wp + 1; }
            if do_pop  { rp = rp + 1; }
            if do_push && !do_pop      { count = count + 1; }
            else if do_pop && !do_push { count = count - 1; }
        }
    }

    assign o_data  = rdata;
    assign o_count = count;
    assign o_empty = count == 0;
    assign o_full  = count == (1 << ADDR_W);
}

Veryl 用 always_ff 表示時序邏輯、if_reset 統一處理重設；= 在 always_ff 內代表「下一拍生效」，等於 Verilog 的 <=。

testbench TestFifo 依序檢查：重設後為空、push 三個位元組、依序 pop 出 0x11 / 0x22 / 0x33、清空後再填滿 256 筆、滿了之後不能再 push。這些 $assert 就是 EDA 模擬階段最早、也最便宜的把關。

5.3 全面驗證：四種實作，同一個答案

為什麼 8,660 個閘會變成 86 個 iCE40 元件？

因為「閘」和「FPGA 元件」不是同一種東西。通用閘網表把 256×8 的記憶體拆成大量正反器與多工器；iCE40 映射時，整塊記憶體被收進 1 個 SB_RAM40_4K，其餘控制邏輯才用 LUT4 與 DFF 實現。元件數不能跨技術直接比較，必須在同一個製程／元件庫裡看 PPA。

ASIC 的每週期能量分解（畫面數值，總和約 0.70 pJ）很值得注意：

5.7 這一輪學到什麼

同一份 125 行的 FIFO，在四個抽象層級都通過同一個 testbench，卻有完全不同的成本結構：通用閘 8,660 個元件、FPGA 86 個元件（1 個 BRAM）、ASIC 166 個元件（1 個 SRAM）。EDA 的價值不是「把電路畫出來」，而是讓這些差異可以被量測、被比較、被選擇。 如果沒有合成與佈局繞線，設計者只知道「邏輯對」，不知道「這樣做值不值得」。這正是 EDA 從「輔助繪圖」升級為「設計方法」的關鍵。

6實作二：Inc16 與迷你 EDA

第二個設計回到 Nand2Tetris 的教學語境：用 hdl.html 模擬一個 16 位元遞增器 Inc16，再按「合成 LUT」看它如何被映射到 FPGA 與 ASIC。這個例子小到可以完全看懂，正好用來拆解「合成」到底做了什麼。

為什麼 LUT4 的數量不是「224 ÷ 4」？

因為一個 LUT4 不是「4 個閘」，而是一張 16 位元的真值表：任何 4 個輸入的布林函數都可以用它實現。合成器會把邏輯切成 4 輸入的切集（cut），再把每個切集的真值表燒進 LUT。因此 224 個閘可能變成 60 個 LUT4，也可能更多或更少，取決於電路結構與化簡。ASIC 則沒有 LUT，必須用 NAND2、INV、AOI21 等標準元件重新組出同樣的函數，所以又是另一組數字。

6.3 這個例子的意義

Inc16 只是一個 16 位元加一，卻已經完整展示了 EDA 的核心迴圈：描述（HDL）→ 模擬（.tst）→ 合成（閘）→ 映射（LUT / 標準元件）→ 佈局繞線（座標）→ 時序（Fmax）。對初學者來說，這比直接看一顆 CPU 更容易建立心智模型；對有經驗的設計者來說，它提醒你：每一個階段都可能改變數字，但行為必須保持一致。

7實作三：RISC-V CPU 與「放不下」

第三個設計把規模拉大：veryl2chip 內建的單週期 RV32I 核心 RiscvCore，以及加上程式 ROM、資料 RAM、LED 的 RiscvSoc。這一輪最重要的收穫不是「跑得多快」，而是EDA 如何在編譯期就告訴你「這顆晶片放不下」。

7.1 單週期 RV32I：功能對，但放不進 FPGA

選擇「RV32I 單週期 CPU」範例，直接跳到 FPGA 的 ⑤ Placement。合成結果是 9,175 → 9,151 個閘、5,337 個 LUT4、1,056 個 DFF；接著佈局繞線回報：

佈局繞線失敗：design does not fit: needs 5441 LCs (the device has 5280) and 167 IO pins (the package has 39)

iCE40UP5K-SG48 只有 5,280 個 LC、39 個 I/O 腳。這個核心的暫存器檔用正反器實現，再加上單週期 CPU 的資料路徑，結果超出 161 個 LC，且 I/O 需求遠超封裝腳數。工具沒有把錯誤留到燒錄或上電才發生，而是在佈局階段就明確拒絕，並建議改用「RISC-V SoC（FPGA）」範例或 ASIC 流程。

這一幕就是 EDA 的價值

「放不下」不是設計者的疏忽，而是架構與資源的衝突。EDA 把這個衝突量化成兩個數字（5,441 > 5,280、167 > 39），讓設計者可以在改架構（多週期、把暫存器／記憶體放進 BRAM）、換晶片（更大的 FPGA）、或改流程（走 ASIC）之間做選擇。如果沒有這一關，這些數字要等到板子回來才會變成除錯成本。

7.3 從「放不下」到「跑起來」：架構決策被 EDA 推動

這一輪完整展示了 EDA 如何參與架構決策，而不只是被動實現：

  • 單週期 → 多週期：減少每個時脈的組合邏輯與資料路徑，換取較低的資源與較高的 Fmax 餘裕。
  • 暫存器 → BRAM：把 32×32 的暫存器檔與記憶體放進 block RAM，LUT4 用量從 5,337 降到 1,164。
  • 程式 ROM 常數化：合成器把只被這個程式用到的硬體移除（未用的暫存器、移位器、byte load 等），所以 SoC 的閘數遠小於完整核心。
  • 位元流驗證：Fmax 17.0 MHz ≥ 12 MHz，才敢說「這顆設計可以在這塊板子上跑」。

這也解釋了為什麼 IC 設計不是「寫完 RTL 就結束」：RTL 只是提案，EDA 才是把提案變成可執行承諾的過程。

8從操作看 EDA 的五個價值

把三次操作放在一起看，EDA 的價值可以歸納成五點。每一點都對應到本報告量到的具體數字。

8.1 正確性：四種實作，一個答案

FIFO 的「全面驗證」把同一個 testbench 跑在 RTL、通用閘、iCE40、標準元件四種實作上，結果 4/4 一致。這個矩陣的意義是：合成器也是軟體，也會有 bug；用同一組測試去驗證合成前後，是最實際的交叉檢查。更嚴謹的流程還會做形式等價檢查（formal equivalence），用數學證明兩份網表在所有輸入下行為相同。

8.2 可實現性：在編譯期就說「放不下」

RV32I 單週期核心需要 5,441 LC，但 iCE40UP5K 只有 5,280 LC；需要 167 個 I/O，但封裝只有 39 腳。EDA 在佈局階段就給出明確的失敗訊息，還附上建議。這種「早期失敗」比「晚期失敗」便宜幾個數量級：在 FPGA 上，它只損失幾分鐘；在 ASIC 上，它可能避免一次數百萬美元的光罩錯誤。

8.3 量化：把 PPA 取捨變成表格

FIFO 的 FPGA 與 ASIC 比較，把「哪個比較好」拆成 9 個指標：邏輯資源、記憶體、面積、繞線、關鍵路徑、Fmax、每週期能量、功耗。沒有 EDA，這些只能靠猜；有了 EDA，設計者可以說「我需要 48 MHz、低功耗、可重燒，所以選 FPGA」或「我要 500 MHz、量產一億顆，所以走 ASIC」。工程決策的前提是可比較的數字。

8.4 生產力：瀏覽器裡的分鐘級迭代

這次的迭代速度：FIFO 模擬 0.07 秒、四種實作全面驗證 6.3 秒、RISC-V SoC 的佈局繞線約 40 秒、虛擬板燒錄與開機在分鐘內完成。這些數字在 20 年前需要工作站與授權排隊，現在只要一個瀏覽器分頁。WebAssembly 與開源工具鏈把 EDA 的入門門檻降到「打開網址就能用」，這對教學、原型與小團隊特別重要。

8.5 透明性：每一個階段都可以點進去看

veryl2chip 與 hack-computer 都把中間結果畫出來：LUT 的真值表、標準元件的位置、繞線的 net、關鍵路徑的每一段延遲、退火佈局的過程。商用工具當然也能產生報告，但通常藏在指令與 log 裡；教學工具把「黑盒子」打開，讓學習者看見演算法如何改變結果。例如 Inc16 的 224 個閘變成 60 個 LUT4，或 FIFO 的 8,660 個通用閘變成 86 個 iCE40 元件，這些「數量級跳躍」只有在中間階段才看得懂。

也要知道限制

本報告的 ASIC 數字來自 vlib 教學模型（veryl2chip 另支援 SKY130 開放 PDK），不是商業 signoff；hack-computer 的 MicroSyn / MicroPnR 也是簡化版。真實 tapeout 需要 foundry 的 PDK、Liberty / SPEF / SDC、商用 STA 與 DRC / LVS 工具，以及 silicon validation。把這些數字當成「理解流程與趨勢」的工具，而不是「可以直接下線」的保證。

11結論

EDA 是 IC 設計的「實現層」。 它接收人類寫下的 RTL，經過模擬、合成、映射、佈局、繞線、時序與功耗分析，最後輸出位元流或 GDSII。它不只是畫圖或模擬，而是一套把「功能意圖」轉換成「物理現實」的工具鏈與方法學。

這次的實作讓我印象最深的是抽象層級的落差：一個 256×8 的 FIFO，在通用閘是 8,660 個元件，在 FPGA 是 86 個元件（1 個 BRAM），在 ASIC 是 166 個標準元件（1 個 SRAM）。同一個行為，不同的實現，Fmax 從 48.3 MHz 跳到 493.9 MHz，每週期能量從 25.9 pJ 降到 0.70 pJ。這些數字不是課本上的形容詞，而是按了幾下滑鼠、跑了幾十秒之後，工具根據真實的元件庫與繞線算出來的。

另一個印象是失敗的價值：單週期 RV32I 核心因為 5,441 > 5,280 個 LC、167 > 39 個 I/O 而「放不下」。這個失敗不是挫折，而是 EDA 最有用的功能之一：它讓設計者在花錢之前就知道架構與資源的衝突，然後用多週期、BRAM、換晶片或改流程來解決。最後 RISC-V SoC 以 1,164 個 LUT4、17.0 MHz 的位元流在虛擬板上亮出 LED = 55，完成了從 RTL 到實際運行的閉環。

所以，IC 設計的 EDA 是什麼？ 它是把「我想要一顆會算 Fibonacci 的晶片」變成「這顆晶片在 17 MHz 下、用 1,227 個邏輯單元、可以燒進這塊板子」的那一整套工具、資料與方法。沒有它，現代晶片的複雜度無法被管理；有了它，設計者才能在速度、功耗、面積與成本之間，做出有根據的選擇。

給第一次接觸 EDA 的人

不要從「記住所有工具名稱」開始。先從一個小設計（例如 FIFO 或 Inc16）走一次完整流程：寫 RTL → 跑 testbench → 看波形 → 合成 → 看閘／LUT → 佈局繞線 → 看 Fmax。當你看到同一份程式碼變成不同的元件、不同的數字，你就會真正理解 EDA 在做什麼。

A.3 名詞對照

名詞意思
RTLRegister-Transfer Level，暫存器轉移層級；用時脈與暫存器描述電路行為，是合成工具的輸入。
Testbench用來測試設計的「測試電路」：產生時脈、餵輸入、檢查輸出。
Synthesis邏輯合成：把 RTL 轉成閘級網表，並做化簡與最佳化。
Technology mapping技術映射：把通用閘對應到特定製程的 LUT、標準元件或記憶體。
Placement / Routing佈局／繞線：決定元件位置，再用金屬線或可程式開關連接。
CTSClock Tree Synthesis，時脈樹合成：把時脈均勻地送到所有正反器，控制 skew。
STAStatic Timing Analysis，靜態時序分析：不跑模擬，用延遲模型檢查 setup / hold 是否滿足。
PPAPerformance、Power、Area：效能、功耗、面積，IC 設計的三大取捨。
DRC / LVSDesign Rule Check / Layout Versus Schematic：檢查版圖是否符合製程規則、是否與電路一致。
PDKProcess Design Kit：製程廠提供的設計套件（元件模型、規則、Liberty 等）。
DFT / ATPGDesign for Test / Automatic Test Pattern Generation：讓晶片可被測試，並自動產生測試向量。
GDSII積體電路版圖的交換格式，是送給晶圓廠的「施工圖」。
BitstreamFPGA 的設定檔：每個 LUT 的真值表與每個繞線開關的開關狀態。
LUT44 輸入查表：16 位元真值表，可實現任意 4 輸入布林函數。
DFFD 型正反器：時脈邊緣觸發的 1 位元儲存元件。
BRAM / SRAMFPGA 的塊狀記憶體 / ASIC 的靜態隨機存取記憶體巨集。
Tapeout送片：把 GDSII 送進晶圓廠製作光罩並生產。
NRENon-Recurring Engineering，一次性工程成本（光罩、設計、驗證）。
